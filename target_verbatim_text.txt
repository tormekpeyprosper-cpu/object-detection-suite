Abstract
Standard object detectors are built around broad categories. Point a pre-trained YOLO model trained on Microsoft COCO at a camera feed (Lin et al., 2014; Redmon et al., 2016) and it will put a 'person' box around me just like anybody else. That works fine if you only want a headcount at a gate. It falls short when you need to take attendance in a Pentecost University lecture room or check who is walking into a lab, because the system has to know it is actually me, Tormekpey Ian Prosper, and not just someone standing in frame.
To get around that, I put together my own dataset from scratch. Over a few days on campus and around my hostel, I shot 1,021 phone photos across dim bedrooms, harsh afternoon sun, backlit hallways, and group shots with up to eight classmates. Labeling all of them took time. Whenever other people appeared in a picture, I drew a bounding box around myself and left everyone else unboxed as background negatives. That forces the training loss to push back if the network mistakes a friend for me.
I fine-tuned a lightweight YOLO26n model (Ultralytics Inc., 2026) in the cloud for 100 epochs, and the run finished in under six minutes. On validation, the model hit 91.7% precision, 80.0% recall, 80.4% mAP@50, and 34.9% mAP@50-95, gaining 3.2 percentage points in mAP@50-95 over my earlier 945-image baseline. The saved weights file comes out to only 5.54 MB. I hosted the model on Google Cloud Run in europe-southwest1 and placed a FastAPI proxy on Vercel in front of it (Ramírez, 2024; Vercel Inc., 2024). Uploaded photos stay strictly in RAM during inference and are cleared right afterward so nothing ever touches disk. Users can test the detector directly from an HTML5 web page or an Android React Native app (Meta Platforms Inc. & Expo Project, 2024), and the full 1,021-image dataset is backed up in Google Drive.

1. Introduction
1.1 Background and Problem Statement
Out-of-the-box object detectors are trained on generic object classes. If you run a standard model trained on the Microsoft COCO dataset (Lin et al., 2014) or the original YOLO family (Redmon et al., 2016) on a campus camera, anyone walking past gets labeled 'person'. That works well enough when an administrator just needs a headcount at an entrance. Once you need to record lecture attendance in our department or verify who walks into a restricted lab, a generic 'person' tag is no help at all.
That gap is what pushed me to try this project. I wanted to find out whether an undergraduate with no dedicated GPU at home could train a detector to pick out one specific individual, myself, using 1,021 phone photos taken around Pentecost University. Campus conditions made it tricky. Midday sun washes out facial details, whereas hostel rooms are often dim and shadowy. Since students rarely walk alone, I also needed enough multi-person photos to stop the model from flagging my friends by mistake, while keeping inference fast and never saving uploaded images on a server.

1.2 Aim and Objectives
My goal in this project was to train, test, and deliver a YOLO26n detector (Ultralytics Inc., 2026) that picks me out reliably in everyday photos. To make the workload manageable, I worked through seven steps:
1. Collecting and hand-labeling 1,021 phone photos covering solo shots, strong backlighting, cluttered indoor backgrounds, and group pictures with classmates.
2. Fine-tuning a lightweight YOLO26n model on a rented cloud GPU and comparing it against an earlier 945-image baseline run.
3. Checking validation numbers across precision, recall, mAP@50, mAP@50-95, and the F1-confidence curve.
4. Hosting the trained checkpoint inside a Google Cloud Run container on the Ultralytics platform (Ultralytics Inc., 2026).
5. Putting a FastAPI proxy on Vercel (Ramírez, 2024; Vercel Inc., 2024) in front of the model so uploads stay in RAM and Python's garbage collector clears image buffers right after inference.
6. Building an HTML5 canvas web page alongside an open-access React Native Android app (Meta Platforms Inc. & Expo Project, 2024) that anyone can open without signing up.
7. Running automated smoke tests against the live endpoint to measure roundtrip latency, verify uptime, and confirm zero disk leaks.

1.3 Scope and Limitations
Everything from snapping raw photos and drawing labels to checking training curves, writing the FastAPI proxy, and shipping the web and mobile clients is covered in this report. The detector itself only looks for one class: me in static photos or camera captures. Running inference on Cloud Run behind Vercel means both apps need a working internet connection, and Vercel blocks uploads above 4.5 MB (Vercel Inc., 2024). Because the apps read from a single phone or laptop camera, the model only works on flat 2D images and cannot estimate depth.

1.4 Significance of the Study
Building and deploying this system showed me you do not need expensive lab GPUs to ship real computer vision software. Transfer learning on top of YOLO26n (Ultralytics Inc., 2026) got solid accuracy out of a little over a thousand phone photos and less than six minutes of cloud training. Just as important, the FastAPI proxy (Ramírez, 2024) proved that person-specific detection can work without saving anyone's photos to disk, because frames stay in RAM and are wiped the moment predictions come back.

2. Theoretical Background
2.1 Object Detection and YOLO
Early computer vision pipelines leaned on hand-engineered descriptors like Haar cascades, Histogram of Oriented Gradients, and SIFT, plus open-source computer vision toolkits like OpenCV (Bradski, 2000). Those classical filters broke down quickly outside controlled lighting whenever camera angles shifted or backgrounds got busy. Convolutional neural networks replaced them because convolutional layers learn edges, textures, and high-level shapes straight from raw pixel grids.
Today's neural object detectors split mainly into two-stage and one-stage designs. Table 1 puts the two families side by side.

Table 1: Two-stage and one-stage object detectors
Detector Paradigm | Representative Architectures | Inference Methodology | Suitability for this Project
Two-stage | R-CNN, Fast R-CNN, Faster R-CNN (Ren et al., 2017) | Generates candidate region proposals first, then extracts features and classifies each region separately. | Strong accuracy on benchmarks, but too heavy and slow for responsive mobile scanning.
One-stage | SSD, RetinaNet, YOLO family (Redmon et al., 2016), YOLO26n (Ultralytics Inc., 2026) | Predicts bounding box coordinates and class probabilities in a single forward pass across the grid. | Fast, compact, and light enough to answer mobile and web requests in well under a second.

I picked YOLO26n (Ultralytics Inc., 2026) largely because its trained weights take up only 5.54 MB. That small footprint keeps container cold starts short on Cloud Run and lets the live API reply in under 600ms.

2.2 Evaluation Metrics & Mathematical Formulations
To judge whether Run 2 actually improved over Run 1 without relying on guesswork, I tracked five standard detection metrics:
1. Precision (P) asks how often the model is right when it draws a box and claims it found me: Precision = TP / (TP + FP) = 91.7%. Keeping precision high matters because false positives mean mislabeling my classmates.
2. Recall (R) measures how many times the model caught me out of all validation images where I actually appeared: Recall = TP / (TP + FN) = 80.0%. Good recall keeps detections steady even in dim hostel lighting.
3. Overall accuracy across candidate proposals follows Accuracy = (TP + TN) / (TP + TN + FP + FN), though it is less informative on dense image grids than precision and recall.
4. F1-Score balances precision and recall via their harmonic mean: F1 = 2 * (Precision * Recall) / (Precision + Recall) = 0.854 at the default threshold, peaking at 0.857 when confidence reaches 0.61.
5. Mean Average Precision (mAP) integrates the area under the precision-recall curve (Lin et al., 2014). I tracked both mAP@0.50 (80.4%), which counts boxes overlapping ground truth by at least 50%, and the stricter mAP@0.50:0.95 (34.9%), which averages AP across ten IoU cut-offs from 0.50 up to 0.95.
6. Why PR-AUC beats ROC-AUC here: standard ROC curves plot True Positive Rate against False Positive Rate, which works well for balanced binary classifiers. In object detection, however, thousands of background grid cells count as true negatives in every single frame. That huge TN denominator pushes the false positive rate close to zero and artificially inflates ROC-AUC above 0.98, whereas Precision-Recall curves evaluate actual foreground predictions without being skewed by empty background.

2.3 Bounding Box Coordinate Mathematics and Cross-Platform Rendering
YOLO emits each predicted box as four normalized values between 0.0 and 1.0 relative to image width W_img and height H_img (Redmon et al., 2016):
box = [x_center, y_center, width, height]
Converting those numbers into clean boxes on both desktop browsers and tall smartphone screens took a bit of coordinate math:
- Top-left pixel origin: x_min = (x_center - width / 2) * W_img and y_min = (y_center - height / 2) * H_img.
- Box width and height in pixels: box_width = width * W_img and box_height = height * H_img.
- Duplicate box suppression: Non-Maximum Suppression (NMS) removes overlapping boxes whose Intersection over Union meets or exceeds 0.50, using IoU(A, B) = Area(A ∩ B) / Area(A ∪ B).
- Browser canvas scaling: the HTML5 canvas client maps predictions using sx = W_canvas / W_img and sy = H_canvas / H_img.
- Mobile viewport scaling: inside React Native (Meta Platforms Inc. & Expo Project, 2024), boxes scale uniformly by s = min(W_viewport / W_img, H_viewport / H_img) with letterbox offsets (dx, dy) so tall phone screens never stretch the box away from my face.

2.4 Retrieval-Augmented Generation (RAG) Architecture
Instead of baking user records into the neural network, the system splits visual recognition from data lookup. YOLO26n (Ultralytics Inc., 2026) only has to locate me and emit a class label with a confidence score. Downstream services can then pass that verified identity token to a Supabase pgvector index to fetch attendance logs, lab permissions, or coaching notes (Apaak, 2024), while the raw camera frame never leaves volatile memory.

4. Methodology
4.1 Data Collection
No public dataset contains my face, so I built one myself from scratch. Over several days on campus and inside my hostel, I captured 1,021 JPEG images on my phone under everyday conditions: harsh noon sunlight, dim bedroom lamps, bright backlit corridors, slight motion blur, and group shots with two to eight classmates beside me. A local backup of the full photo folder also sits on my machine at C:\Users\torme\Downloads\exp2_dataset_photos.

4.2 Annotation
Every photo was annotated in standard YOLO text format (class_id x_center y_center width height), normalized from 0.0 to 1.0 (Redmon et al., 2016).
I mapped myself to Class 0 ('Prosper'). Whenever friends or classmates appeared in group photos, I deliberately left them unlabeled. Leaving them unboxed makes the training loss penalize the network whenever it confuses someone else for me, and over 100 epochs the model learned to treat everyone else as background. I also reviewed bounding box edges manually so each box stayed snug around my head and torso.

4.3 Training Setup and Runs
I compared two training runs during development. The baseline ('exp') trained YOLOv8n on 945 images, while the production run ('exp-2') moved up to YOLO26n (Ultralytics Inc., 2026) with the expanded 1,021-image dataset on a cloud NVIDIA RTX PRO 6000 GPU (97,252 MiB VRAM) paired with an AMD EPYC 9655 host. Table 3 lists the exact settings used for exp-2.

Table 3: Training setup and hyperparameters (exp-2)
Hyperparameter / Setting | Configured Value
Cloud Platform | Ultralytics Platform Cloud Training (Ultralytics Inc., 2026)
Hardware Accelerator | NVIDIA RTX PRO 6000 Blackwell Server Edition (97,252 MiB VRAM)
Host Compute | AMD EPYC 9655 96-Core Processor (384 threads, 1.5 TB Host RAM)
Base Model & Version | YOLO26 Nano using yolo26n.pt pre-trained weights (Ultralytics Inc., 2026)

Total Training Duration | 340.6 seconds (~5.67 minutes across all 100 epochs)

The 100-epoch SGD run wrapped up in 340.6 seconds. Enabling mosaic, horizontal flips, and random erasing helped the model keep track of me even when glasses, hands, or other students blocked part of my face.

5.2 Analysis of the Improvement
Precision climbed to 91.7%, meaning roughly nine out of ten boxes drawn by the model are genuine hits, while recall reached 80.0% (catching four out of five tougher shots). Even though mAP@0.50 stayed essentially flat at 80.4%, the stricter mAP@0.50:0.95 jumped from 31.7% to 34.9% (a 10.1% relative gain). That jump confirms the second model aligns boxes much more tightly around me than the baseline did.
In Run 1, bounding boxes tended to wobble slightly whenever the camera tilted or moved off-center. Raising the input resolution to 992x992 and adding more group photos fixed much of that drift, and negative sampling kept false positives on classmates at zero during validation.

6.2 FastAPI Gateway on Vercel
A serverless FastAPI gateway (Ramírez, 2024; Vercel Inc., 2024) sits between both client apps and Cloud Run, exposing /api/health and /api/detect under three design rules:
1. Anyone can open the studio and run detections right away without signing up or logging in.
2. Uploaded frames live strictly inside volatile RAM via Pillow (Clark & Contributors, 2024), and a guaranteed finally block executes 'del image_bytes' and 'gc.collect()' right after inference so zero bytes ever hit disk or database storage.
3. Payloads larger than 4.5 MB are stopped with an HTTP 413 response to match Vercel's serverless body ceiling and avoid gateway timeouts.

6.3 Web Application
The web client is a Vite HTML5 Canvas studio hosted live on Vercel (Vercel Inc., 2024): https://object-detection-suite.vercel.app
Visitors can drag and drop photos or capture frames straight from a webcam, inspect boxes drawn onto the canvas in real time, and wipe the local bitmap from browser memory with the Clear button.

8. Challenges and Lessons Learned
1. High-resolution smartphone cameras regularly produce 10 MB to 15 MB JPEGs, which triggered HTTP 413 errors against Vercel's 4.5 MB limit (Vercel Inc., 2024). Downsampling oversized frames on the web client and using Pillow resizing (Clark & Contributors, 2024) in FastAPI resolved the upload failures.
2. Keeping uploaded bytes strictly out of disk storage meant watching out for lingering Python references in RAM. Wrapping inference in a try-finally block and explicitly deleting image_bytes before calling gc.collect() kept memory usage flat.
3. Tall mobile screens initially caused bounding boxes to drift away from my face because raw image aspect ratios differed from preview containers. Switching to isotropic scaling with letterbox offsets fixed alignment across devices.
4. Shipping an Ultralytics API key inside client code would let anyone extract credentials from the bundle. Routing every request through the server-side FastAPI proxy on Vercel kept the secret key hidden on the server.
5. More than any hyperparameter tweak, dataset curation made the biggest difference. Leaving classmates unannotated in group photos taught the network who not to box far more effectively than tuning learning rates alone.

9. Conclusion and Recommendations
9.1 Conclusion
This project shows that regular smartphone photos and rented cloud GPUs are enough to train and ship a working personal object detector. Fine-tuning YOLO26n (Ultralytics Inc., 2026) on 1,021 images reached 91.7% precision, 80.0% recall, 80.4% mAP@50, and 34.9% mAP@50-95. Connected to Google Cloud Run through a zero-storage FastAPI proxy on Vercel (Ramírez, 2024; Vercel Inc., 2024), both the web and Android apps return live boxes in under 600ms without ever saving uploaded photos.

9.2 Recommendations
1. Export quantized INT8 ONNX, TFLite, or CoreML weights so mobile devices can run inference locally offline without relying on mobile data.
2. Expand the dataset to cover additional students and staff, enabling multi-class classroom attendance or sports program monitoring (Apaak, 2024).
3. Pair the detector with pose-estimation toolkits such as MediaPipe (Lugaresi et al., 2019) or OpenPose (Cao et al., 2021) and dual-camera depth estimation for 3D movement and biomechanics tracking.
